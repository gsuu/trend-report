# 상세페이지 내용 v3.1 — 큐레이션 톤으로 보정 회의록 (2026-05-24)

> 5번째 회의([article-content-redesign-v3-direction-2026-05.md](article-content-redesign-v3-direction-2026-05.md))에서 매거진+카드 하이브리드 형식을 합의했지만, 카드 셋 5장(결정 한 줄·점검 질문 3개 등)이 매거진성을 추구한다면서 여전히 **실무 액션 중심 톤**으로 남아 있다는 사용자 피드백 — *"점검질문·결정한줄 이런거보다는 우리가 왜 이 글을 큐레이션 했는지, 어떤 내용이 있는지, 같이 살펴보면 좋은 글은 뭐가 있는지가 들어가게"*.
>
> 이번 짧은 보정 회의는 **5번째 회의의 카드 셋만 큐레이션 톤으로 재정의**한다. 다른 합의(하이브리드 채택·매거진 블록 씬→흐름→함의 가이드·심화 섹션·시각 분리)는 그대로 유지.

## 진단 — 5번째 회의의 한계

**편집장**: 5번째 회의에서 매거진+카드 하이브리드를 정했고 그 자체는 유효합니다. 다만 카드 5장 — 🎯 결정 한 줄, 📊 숫자, 🖼️ 화면, 🧭 클라이언트 적합, ❓ 점검 질문 3개 — 는 결국 **실무 액션 카드**입니다. 사용자 피드백은 매거진의 큐레이션 톤은 그게 아니라 **편집자가 독자에게 안내하는 톤** 이라고 짚었습니다.

**잡지 에디터**: 동의합니다. 잡지에서 글 옆에 붙는 박스는 보통 "에디터의 픽 — 왜 이 글을", "이 기사에서 만나는 사람·장면·숫자", "이 다음에 읽으면 좋은 글" 같은 **큐레이션 인덱스** 형태입니다. 액션이 아니라 안내.

**매거진 편집 라이터**: 5번째 회의 카드는 라이터 입장에서도 약간 어색했어요. "결정 한 줄"·"점검 질문 3개"는 클라이언트 미팅용 자료의 결인데, 잡지를 읽는 독자(우리 직원)는 그 자료를 펴는 시점이 아닙니다. 펴는 시점은 **"오늘 무엇을 읽을까"** 찾는 순간.

**CTTD 시니어 기획자**: 매거진 글이 클라이언트 미팅에 인용되는 가치는 그대로 유지하되, 그 인용은 본문 안 `> 데이터:`·`> 인용:` 인라인 박스로 자연스럽게 들어가게 합니다. 카드 셋이 그걸 뽑아내는 역할을 할 필요 없음 — 본문 자체에서 인용 가능.

## 새 카드 셋 (보정안)

5번째 회의의 카드 5장을 폐기하고 **3블록 큐레이션 인덱스**로 교체.

| 블록 | 내용 | 데이터 출처 |
|---|---|---|
| 📝 **에디터의 큐레이션 노트** | "왜 이 글을 이번 호에 골랐는지" 1-3문장. 작가·에디터의 선택 이유. | 메타 `큐레이션 사유` 신규 (의무) |
| 📖 **이 글에서 만나는 것** | 본문에서 다루는 핵심 요소 3-5개 — 사람·장면·숫자·도구·브랜드 중 어느 것이라도. 액션 아니라 콘텐츠 가이드. | 메타 `이 글에서 만나는 것` 신규 (선택, 비면 본문 매거진 블록에서 자동 추출) |
| 📚 **같이 살펴보면 좋은 글** | 우리 매거진 누적 글 중 관련 글 + **외부 참고 글**까지. 3-6개. | 직전 결과 `sameBrandIssues` / `sameFlowIssues` + 새 메타 `외부 참고` (선택) |

각 블록의 톤은 **편집자가 독자에게 안내하는 톤**. "이걸 하세요"가 아니라 "이걸 만나실 거예요".

## 5번째 회의의 카드 5장 — 각각 운명

| 카드 5장 | 운명 |
|---|---|
| 🎯 결정 한 줄 (pullQuote) | ❌ 폐기 — 매거진 블록 안 한 단락이 흡수 |
| 📊 숫자 한 개 (근거 데이터) | ❌ 카드 위치 폐기, **본문 안 `> 데이터:` 인라인 박스로 옮김** (기존 패턴 활용) |
| 🖼️ 화면 한 장 | ❌ 카드 위치 폐기, hero 우측 또는 본문 갤러리 그대로 |
| 🧭 클라이언트 적합 | △ **약화**. hero meta-row의 작은 라벨로만 노출. 카드 자리 차지하지 않음 |
| ❓ 점검 질문 3개 | ❌ 폐기 — 매거진의 결이 아님. 본문 매거진 블록 마지막에 질문 1개로 끝내는 잡지 결로 충분 |

## 신규 메타 2종 — 라이터 작성 부담 최소화

| 메타 | 의무·선택 | 자동 fallback |
|---|---|---|
| `큐레이션 사유` | **의무 (모든 글)** | 비면 본문 매거진 블록 첫 단락(씬) 자동 추출. 단 폴백은 권장하지 않고 라이터가 직접 1-3문장 작성 권장 |
| `이 글에서 만나는 것` | 선택 | 비면 본문 매거진 블록에서 **고유명사·숫자·날짜**를 정규식으로 자동 추출해 3-5개 불릿 생성 |
| `외부 참고` | 선택 | 라이터가 외부 글 URL 1-3개 명시. 없으면 블록은 누적 글만 |

## 보정 후 신규 글 구조

```
┌─ Hero (직전 회의 결과 + clientFit 작은 라벨로 약화) ─┐
├─ 📰 매거진 블록 (의무, 600-900자) ───────────────────┤
│   씬 → 흐름 → 함의 (3단락, 라벨 없는 흐르는 글)
│   본문 안에 `> 데이터:`·`> 인용:` 인라인 박스 자유
│
├─ 🗂️ 큐레이션 인덱스 (3블록) ──────────────────────┤
│   📝 에디터의 큐레이션 노트 (왜 이 글을)
│   📖 이 글에서 만나는 것 (사람·장면·숫자·도구)
│   📚 같이 살펴보면 좋은 글 (누적 + 외부)
│
├─ 📚 심화 섹션 (선택, H3 단위 1-3개) ───────────────┤
│
└─ Footer · sidebar(축소) · 출처 검증 박스 ─────────┘
```

5번째 회의의 `매거진 블록` + `심화 섹션` + `시각 분리`는 그대로 유지. 카드 5장만 큐레이션 3블록으로 교체.

---

## 합의 사항 3가지

1. **카드 5장 → 큐레이션 인덱스 3블록 교체.** 톤이 "실무 액션"에서 "**편집자 안내**"로 이동.
2. **`meeting_question` / `pullQuote` 메타 자체를 폐기**. 직전 4번 회의에서 만든 `💬 클라이언트에게 묻기` 박스, `📌 슬라이드 인용` 박스도 함께 폐기. 매거진의 결과 어울리지 않는 액션 박스 모두 제거.
3. **신규 메타 2종(`큐레이션 사유`·`이 글에서 만나는 것`·`외부 참고`) 도입**. `큐레이션 사유` 의무 1개만 라이터가 추가 작성하면 됨 — 1-3문장.

## 우선순위와 다음 액션 — 5번째 회의 7단계와 통합

5번째 회의의 7단계를 그대로 따르되, **카드 셋 부분만 v3.1 보정안**으로 진행:

| 단계 | 작업 | 상태 |
|---|---|---|
| 1. parser | `articleVersion: "v3"` 마크 + 신규 메타 3종 (`큐레이션 사유` / `이 글에서 만나는 것` / `외부 참고`) + 자동 fallback. `meeting_question` / `pullQuote` payload 필드는 호환 위해 유지하되 v3 글에선 비움 | 대기 |
| 2. App.vue | v3 분기에서 카드 5장 대신 **큐레이션 인덱스 3블록** 렌더. `💬 클라이언트에게 묻기` / `📌 슬라이드 인용` 박스 v3에서 숨김. `articleNature` 배지도 v3에서 숨김. 사이드바의 `회의 질문` 카드 제거 | 대기 |
| 3. magazine-writing-standard | v3 형식 절을 보정안으로 — 카드 5장 X, 큐레이션 인덱스 3블록 O. 신규 메타 3종 작성 가이드 | 대기 |
| 4. magazine-writer 에이전트 | v3 출력 형식 명시 — 매거진 블록(씬→흐름→함의) + `큐레이션 사유` 메타 의무 | 대기 |
| 5. magazine-reviewer | v3 검수 항목 — 매거진 3단 흐름 + `큐레이션 사유` 1-3문장 있는지 | 대기 |

| 7. 예시 글 1편 작성 | v3 형식으로 SERVICE 글 1편 작성·검증 | 대기 |
