## 진단 (회의 본론 시작 전)

**편집장**: 4번의 회의로 시스템이 정밀해졌습니다. 그런데 사용자 피드백은 "지금 본문이 매거진 같지도 않고 실무에서 바로 쓰지도 못한다." 두 결이 모두 약하다는 진단입니다.

**잡지 에디터**: 글 한 편 펴 봅니다. `요약(6슬롯)` → `매거진 인사이트(3슬롯+prompt-hint)` → `footer`. 이게 매거진이 아니라 **체크리스트 양식지**입니다. 우리 잡지에서는 한 호 안에서 사건의 결이 흐르고, 작가의 시점이 보이고, 한 단락이 다음 단락을 끌고 갑니다. 지금 본문은 슬롯과 슬롯 사이가 끊어져 있어요. 첫 단락이 다음 단락으로 안 이어집니다.

**실무 헤비유저**: 반대 입장에서도 말씀드릴게요. 저는 회의 직전 매거진을 펼 때 본문 다 읽을 시간이 없습니다. 첫 화면에서 **"이 글에서 회의에 들고 갈 한 줄"·"바로 보여줄 화면 하나"·"점검 질문 3개"** 만 보면 됩니다. 지금은 슬롯이 많은데 정작 결정에 쓰는 정보는 4개로 일정. 나머지는 노이즈가 됩니다.

**CTTD 시니어 기획자**: 두 분 말씀이 정반대 같은데, 사실 한 글을 두 시점에서 읽는 거잖아요. **첫 화면(30초 스캔)** 과 **천천히 읽는 모드(5-10분)** 가 다를 뿐.

**매거진 편집 라이터**: 라이터 입장에서, 지금 한 글에 평균 90분 걸립니다. 슬롯 채우는 데 60분, 글 다듬는 데 30분. 만약 매거진성을 더하면 다듬는 시간이 더 늘고, 실무성을 더하면 체크리스트 추가 시간 듭니다. **두 결을 모두 추가하면 글당 2-3시간** 됩니다. 그건 발행 가능 건수가 절반으로 떨어진다는 뜻.

**잡지 에디터**: 다 채우려 하지 마세요. **매거진은 글의 결, 실무는 카드의 결**. 한 글에 두 결을 모두 쓰되 **시각적으로 분리된 두 레이어**로 갑니다. 위는 흐르는 매거진 한 단락, 아래는 카드 셋. 라이터는 위는 한 번에 쓰고, 아래 카드는 슬롯이지만 글이 아니라 **단어·문장·링크** 단위라 빠릅니다.

## 회의 안건 7개

### 안건 1. 매거진형 vs 실무 요약형 vs 하이브리드 — 어느 방향인가

**잡지 에디터**: 만약 A(순수 매거진형)로 간다면, 슬롯을 다 빼고 한 호에 4-6개의 큐레이션 글만 둡니다. 글 한 편은 자유로운 1500자. 잡지 같지만 우리 운영(주 13-15건 발행)에는 안 맞아요.

**실무 헤비유저**: B(실무 요약형)로 가면 글 한 편이 카드 5장 모음. 잡지가 아니라 **위키 페이지**. 우리 디지털 자산이 위키화되는 건 강력하지만, 이 사이트의 정체성 "매거진"이 빠져요.

**CTTD 비주얼 디자이너**: C(하이브리드)는 회의 직전 들어왔던 옵션. 위는 매거진, 아래는 실무. 두 결을 시각적으로 명확히 갈라야 합니다 — 배경색·간격·타이포 모두.

**시스템 운영자**: 마이그레이션 부담은 C가 가장 적습니다. 위 매거진 블록은 새로 작성, 아래 실무 카드는 직전 4번 회의의 메타·잠금셋 정보를 재배치해 자동 생성 가능. 누적 글도 자동으로 아래 카드 부분이 채워짐.

**합의**: **C 하이브리드 채택**. 위 = 매거진 한 단락(흐르는 글, 작가 시점), 아래 = 실무 카드 셋(즉답 가능 정보). 두 레이어를 시각적으로 분리.

### 안건 2. "매거진 블록"의 형식 — 위 레이어

**잡지 에디터**: 매거진 블록은 슬롯이 아니라 한 흐름의 글이어야 합니다. 다만 잡지의 '인트로 → 본문 → 마무리' 3단 흐름을 따라 라이터에게는 **3개 단락 가이드**를 줍니다. 슬롯이 아니라 가이드.

권장 형식:
1. **씬 (Scene)** — 사건의 도입. "토요일 오후, 강남 신세계 본점 지하에서 ~" 처럼 구체 장면이나 1줄 인용으로 시작. 추상적 일반론 금지.
2. **흐름 (Flow)** — 이 사건이 산업/시장/사용자 행동의 어떤 흐름 위에 놓이는지. 작가의 관점이 가장 강하게 드러나는 단락. 한 가지 입장을 명확히 한다.
3. **함의 (Implication)** — 이 사건이 우리(에이전시·클라이언트·독자)에게 어떤 의미인지 한 단락. 결론 강요 X, 질문 1개로 끝내는 게 잡지 결.

**매거진 편집 라이터**: 슬롯이 아니라 가이드라면 라이터마다 결이 다 다를 텐데요? 그게 매거진의 결이긴 한데 검수 어려워집니다.

**잡지 에디터**: 슬롯 검수가 아니라 **편집 회의**가 필요한 거예요. 우리 잡지는 라이터 글이 들어오면 에디터가 다듬고 톤을 맞춥니다. 자동화는 어렵지만, magazine-reviewer 에이전트가 "씬 → 흐름 → 함의" 3단 흐름이 보이는지, 추상 일반론으로 시작하지 않는지, 함의 단락이 강요로 끝나지 않는지 정도는 검수 가능.

**CTTD 시니어 기획자**: 매거진 블록은 본문 분량 짧게. 600-900자. 길어지면 실무 헤비유저가 펴서 즉답 못 찾습니다.

**합의**:
- 매거진 블록 = 1개 H2 섹션, 본문 3단락(씬 → 흐름 → 함의), 총 600-900자.
- 슬롯 라벨은 본문에 노출하지 않음(독자에게는 흐르는 한 글로 읽힘). 라이터·검수자만 가이드로 인식.
- magazine-reviewer가 3단 흐름·도입·결말 톤만 검수.

### 안건 3. "실무 카드 셋"의 형식 — 아래 레이어

**실무 헤비유저**: 카드 셋은 회의 직전 30초 스캔용. 다음 5장이 한 줄로 늘어서거나 그리드:

| 카드 | 콘텐츠 | 출처 |
|---|---|---|
| 🎯 **결정 한 줄** | 회의에 그대로 들고 갈 1문장 | 직전 회의의 `pullQuote` / `meeting_question` 재활용 |
| 📊 **숫자 한 개** | 핵심 수치 + 기간 + 출처 | 직전 4번 회의 결과 `요약`의 `근거 데이터` 슬롯 또는 본문 `> 데이터:` 박스 |
| 🖼️ **화면 한 장** | 발표용 스크린샷 1장 | `images[0]` 또는 `featured: true` |
| 🧭 **클라이언트 적합** | 어느 클라이언트 유형에 가져갈지 | 직전 4번 회의 결과 `clientFit` |
| ❓ **점검 질문 3개** | 회의에서 던질 짧은 질문 3개 | 직전 4번 회의 결과 `meeting_question` + 본문 `점검 질문` 섹션 첫 3문장 |

**CTTD 비주얼 디자이너**: 카드 5장은 모바일에서 가로 스크롤. 데스크탑은 5열 또는 2열 그리드. 카드마다 강한 색·아이콘.

**CTTD 퍼블리셔**: 카드 데이터는 모두 **기존 payload 필드 재배치**. 새 메타 추가 거의 없음. parser는 거의 무변경, App.vue만 카드 컴포넌트 5종 추가.

**합의**:
- 실무 카드 셋 = 본문 매거진 블록 직후 H2 `## 실무 카드` 섹션.
- 5장 카드(결정 한 줄·숫자 한 개·화면 한 장·클라이언트 적합·점검 질문 3개).
- 모든 카드 콘텐츠는 직전 회의 결과의 메타에서 자동 생성 (라이터 추가 작업 거의 없음).
- 카드는 시각적으로 강하게 — 매거진 블록과 결이 다르다는 게 한눈에 보여야 함.

### 안건 4. 기존 본문 슬롯(`요약 6슬롯` + `잠금셋 3슬롯`)은 어떻게 되나

**편집장**: 이게 가장 큰 결정. 4번 회의로 정한 `요약 6슬롯` + `잠금셋 v2 3슬롯` 두 블록을 폐기하나, 유지하나?

**잡지 에디터**: 폐기 추천. 매거진 블록(위) + 카드 셋(아래) 두 레이어로도 글이 완성됩니다. 슬롯 두 블록은 라이터 시간을 잡아먹고 독자에게는 노이즈.

**실무 헤비유저**: 동의. 다만 한 가지 — 본문 안 깊이 있는 디테일이 사라지면 안 됩니다. **선택적 "심화 섹션"** 으로 본문 아래쪽에 펼치기 가능한 형태로 둘 수 있어요. 카드 셋만 보고 가는 사용자 90%, 심화 펼치는 사용자 10%.

**매거진 편집 라이터**: 좋습니다. 심화 섹션은 라이터 의지로 작성. 본문에 더 풀고 싶은 디테일(화면 단서·구현 조건·내부 정책 같은)이 있으면 채움. 슬롯 강제 X.

**CTTD 시니어 기획자**: 그러면 글 구조는:
1. **매거진 블록 (의무, 600-900자)**
2. **실무 카드 셋 (자동 생성, 라이터는 메타만)**
3. **심화 섹션 (선택, 자유 H3 단위로 1-3개)**
4. (footer: 출처·태그·다음으로 볼 글)

**합의**:
- 4번 회의의 `요약 6슬롯` + `잠금셋 v2 3슬롯` 두 블록 모두 **신규 글에서 폐기**.
- 누적 글은 그대로 (마이그레이션 X — 사이트가 두 형식 모두 호환 렌더).
- 신규 글은 매거진 + 카드 + 심화(선택) 3-블록.

### 안건 6. 카테고리별로 결이 같을지 다를지

**CTTD 비주얼 디자이너**: SERVICE/Design/DEV 모두 같은 형식(매거진 + 카드 + 심화)으로 가도 되나?

**잡지 에디터**: 매거진 블록 톤은 같되 **카드 셋의 5장이 카테고리별로 다르게 구성**되어야 합니다.

| 카테고리 | 카드 셋 5장 |
|---|---|
| SERVICE | 🎯 결정 한 줄 · 📊 숫자 한 개 · 🖼️ 화면 한 장 · 🧭 클라이언트 적합 · ❓ 점검 질문 3개 |

### 안건 7. 사이트 시각 분리 + 마이그레이션 + 작성 시간

**CTTD 비주얼 디자이너**: 시각 분리:
- 매거진 블록: 본문 max-width 660px (지금 760보다 좁게, 잡지 한 컬럼 폭), serif 또는 휴머니스트 sans, 행간 1.7, 풍부한 단락 간격.
- 카드 셋: 본문 max-width 980px (또는 전체 폭), grid 5열, 강한 색 카드.
- 심화 섹션: 매거진 블록과 같은 폭/타이포지만 H3 단위로 펼치기 토글(`<details>`).

**시스템 운영자**: 마이그레이션 — 사이트는 두 형식(누적 슬롯형 + 신규 v3) 모두 렌더해야 합니다. 누적 글은 `요약 6슬롯`/`잠금셋 3슬롯` 그대로 보이고, 신규 글은 매거진+카드. 데이터 스키마 호환 가능.

**매거진 편집 라이터**: 작성 시간 추정:
- 누적(슬롯형): 글당 90분
- 신규(매거진 + 카드 + 심화): 매거진 60-75분 + 카드 자동 + 심화 0-20분 = **글당 60-95분**. 거의 동일하거나 약간 짧음. 매거진 블록을 잘 다듬는 게 핵심.

**합의**:
- 시각: 매거진 좁은 컬럼·풍부한 행간, 카드 넓고 강한 색.
- 마이그레이션: 두 형식 모두 호환 렌더. 신규 글부터 v3.
- 작성 시간: 거의 동일. 라이터의 시간 분배가 슬롯 채우기 → 글 다듬기로 이동.

## 합의 사항 5가지

1. **하이브리드 형식(C) 채택.** 한 글 안에 위 매거진 한 흐름(흐르는 글) + 아래 실무 카드 셋(즉답 정보) 두 레이어를 시각적으로 분리.
2. **매거진 블록은 슬롯이 아니라 가이드.** "씬 → 흐름 → 함의" 3단락 600-900자, 라벨 없이 흐르는 글로 작성. magazine-reviewer는 흐름·도입·결말만 검수.
3. **실무 카드 셋 5장은 메타에서 자동 생성.** 라이터 추가 작업 거의 없음. 카테고리별로 카드 구성이 다르지만 5장 구조·시각 결은 같음.
4. **4번 회의의 `요약 6슬롯`·`잠금셋 3슬롯`은 신규 글에서 폐기**. 메타·검증·갤러리·사이드바·연관 글 추천 등 기능은 모두 유지. 누적 글은 그대로 두고 사이트가 두 형식 호환 렌더.
5. **심화 섹션(선택)** 으로 디테일을 잃지 않게. H3 단위 1-3개, 라이터 의지로 작성.
