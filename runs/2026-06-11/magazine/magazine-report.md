##### 매거진 인사이트

> 검색창이 아니라 대화창이 패션 커머스의 첫 진입점이 되는 흐름을, 무신사가 자체 MCP로 선점하려 합니다.

상품 탐색이 점점 자사 앱 밖, 사용자가 이미 머무는 챗GPT 같은 범용 AI 안에서 먼저 일어납니다. 무신사는 그 대화 안에 자체 인터페이스를 끼워 넣어, 사용자가 카테고리를 고르고 필터를 조정하는 단계를 건너뛰고 상황 질문 한 번으로 코디를 받게 했습니다. 사용자는 무엇을 검색할지 단어를 떠올리는 부담을 덜고, 대신 AI 추천을 신뢰할지 판단하는 일이 새 관문이 됩니다.

이 설계의 핵심은 추천 근거와 스토어 연결의 매끄러움입니다. TPO·가격대·후기를 함께 묶어 답하는 만큼, 추천 카드가 '왜 이 상품인지'를 보여주는지, 클릭 후 도착한 스토어 상세 화면이 대화 맥락(가격대·상황)을 잃지 않고 이어받는지가 전환을 가릅니다. MCP라는 연결 규약은 결국 어떤 상품 정보·후기·재고 신호를 AI에 노출할지 정하는 데이터 설계 문제이기도 합니다.

패션·뷰티 클라이언트가 챗GPT·제미나이 같은 외부 AI에 상품을 이미 연동했다면 'AI 경유 세션의 스토어 도착 후 이탈률'을 일반 검색 유입과 분리해 보고 있는지, 아직 도입 전이라면 어떤 상품 속성과 후기를 AI에 먼저 열지 그 데이터 우선순위부터 설계에 넣을 수 있는지 점검할 지점입니다.

중소 브랜드에게 해외 진출의 진짜 장벽은 시장 자체보다, 채널마다 상품을 따로 등록하고 물류·CS를 새로 세팅하는 운영 부담입니다. 무신사는 국내 무신사 스토어 등록 한 번이 글로벌 스토어와 티몰 글로벌까지 자동 연계되게 묶어, 브랜드가 신규 채널마다 반복하던 작업을 제거했습니다. 브랜드 운영자는 별도 입점 절차·상품 재등록을 덜 하게 되고, 대신 현지 콘텐츠와 가격 전략에 집중할 여지를 얻습니다.

운영자 관점에서 점검할 지점은 '단일 등록, 다중 노출' 구조에서 채널별 차이를 어떻게 흡수하느냐입니다. 통화·사이즈 표기·배송 조건·반품 정책이 채널마다 다른데, 자동 연계가 이를 일괄 변환해 주는지 아니면 브랜드가 수기로 보정해야 하는지에 따라 실제 운영 부담이 갈립니다. 상품 한 건의 정보 구조를 처음부터 다국가·다채널 노출을 전제로 설계해 두는 것이 이 구조의 전제 조건입니다.

패션 클라이언트가 이미 여러 글로벌 마켓플레이스에 입점해 있다면 상품 정보를 채널마다 따로 관리하는지 단일 소스에서 분기시키는지, 아직 해외 채널 확장 전이라면 상품 데이터 모델을 다채널 자동 연계를 전제로 미리 설계할 수 있는지 점검할 지점입니다.

- 오픈서베이 조사에서 생성형 AI 구독은 전년 대비 8.4%p 증가해 9개 카테고리 중 상승폭 1위, 책·웹툰 등 콘텐츠 멤버십은 5.7%p 감소해 하락폭 1위로, 구독 시장이 한쪽으로 쏠리고 있습니다.

- 넷플릭스는 해지 대비 유지 의향이 40.9%p 우위로 강한 락인을 보였고, 음악 스트리밍은 누적 플레이리스트·개인화 데이터가 락인 요인으로 작동합니다.
- 사용자는 해지 대신 계정 공유·구독 일시정지·연간 결제 전환으로 비용을 조절하며, 구독을 일상에 깊이 통합한 채 지출만 관리합니다.

##### 매거진 인사이트

> 구독은 '가입을 늘리는 싸움'에서 '해지를 늦추는 싸움'으로 옮겨갔고, 무엇이 락인을 만드는지가 카테고리를 갈랐습니다.

생성형 AI 구독이 가장 빠르게 늘고 콘텐츠 멤버십이 가장 빠르게 빠지는 대비는, 사용자가 구독을 더 깐깐하게 고른다는 신호입니다. 누적 데이터·플레이리스트·계정 공유처럼 빠져나갈 때 손해를 느끼게 하는 장치가 있는 서비스는 남고, 그렇지 못한 서비스는 먼저 정리됩니다. 사용자는 해지를 아예 안 하는 게 아니라, 일시정지·연간 전환으로 지출을 조절하며 '완전 이탈' 직전에서 머뭅니다.

서비스 설계 관점에서 볼 지점은 해지 흐름과 그 직전 상태값입니다. 가입자 수와 실제 지출이 어긋난다는 사실은, 가입률 지표만으로는 수익 기여를 읽을 수 없다는 뜻이기도 합니다. 일시정지·다운그레이드·연간 전환 같은 '완전 해지 대신의 선택지'를 화면에 명시적으로 제공하는지, 그 선택지들이 사용자에게 잔류 명분(누적 데이터·혜택 유지)을 보여주는지가 유지율을 가릅니다.

패션·뷰티 클라이언트가 멤버십·정기구독을 운영 중이라면 해지 화면에 일시정지·다운그레이드 같은 대안을 제시하고 그 효과를 측정하고 있는지, 아직 구독 모델 도입 전이라면 무엇이 우리 서비스의 락인 요소가 될지(누적 적립·찜·맞춤 데이터)부터 설계에 넣을 수 있는지 점검할 지점입니다.

디자인 판단으로 옮기면, 점검 대상은 '예쁜가'가 아니라 '얼마나 적은 인지 비용으로 끝까지 가는가'입니다. 라벨이 모호한 버튼, 의미가 불분명한 아이콘, 선택지를 과하게 늘린 화면, 진행 상태 피드백이 없는 플로우가 부하를 누적시키는 후보입니다. 연구는 과업 완료율만이 아니라 에너지 소모·집중 가능성·감정 영향 같은 주관적 경험도 함께 측정하라고 권합니다.

##### 요약

- Grid Lanes는 `display: grid-lanes`로 켜는 새 CSS 레이아웃 모드로, 비정형 비율의 이미지와 길이가 제각각인 텍스트를 자동으로 흘려 배치하도록 설계됐습니다.
- 세로 흐름인 Waterfall와 가로 흐름인 Brick 두 방식을 제공하고, `flow-tolerance` 속성(슬라이더)으로 배치 유연성과 결과적인 탭 순서를 조절합니다.
- `fr`·`minmax()`·`repeat()`·`fit-content()`와 `auto-fill`/`auto-fit`를 지원해 기존 Grid 사이징 지식을 그대로 가져갈 수 있습니다.
- Jen Simmons가 작성한 인터랙티브 Field Guide로, 슬라이더를 직접 만지며 배치·탭 순서 변화를 확인합니다.
- 현재 Safari 26.4+에서 동작하며, 다른 브라우저 지원 여부는 Can I Use로 확인하라고 안내합니다.

##### 매거진 인사이트

> "이미지가 들어갈 수 있나"가 아니라 "어떤 배치가 시스템상 허용되나"로 묻게 만드는 레이아웃 모드입니다.

Grid Lanes는 룩북·갤러리·매거진형 카드처럼 비율이 제각각인 이미지와 가변 텍스트를 Masonry 스크립트나 수동 컬럼 분배 없이 흘려 담는 시나리오를 정조준합니다. 핵심은 `flow-tolerance`가 시각적 배치를 바꾸면 탭 순서(키보드 포커스 이동)도 함께 바뀐다는 점이라, 보기 좋은 배치와 접근 가능한 읽기 순서를 동시에 맞춰야 합니다 — iOS Safari 26.4+에서만 먼저 동작하므로 한국 트래픽의 Safari 비중을 감안한 점진적 향상 전제가 필요합니다.

`fr`·`minmax()`·`repeat()`·`fit-content()`를 그대로 받기 때문에 기존 Grid 컴포넌트의 사이징 토큰을 재활용하기 쉽습니다. 다만 단일 브라우저 선행 기능이라 패션 룩북·상품 그리드에 바로 운영 투입하기보다, `@supports (display: grid-lanes)`로 감싸 미지원 브라우저에는 기존 Grid·Flex 폴백을 유지하고, `flow-tolerance` 값별로 키보드 탭 순서가 콘텐츠 의미와 어긋나지 않는지 접근성 QA에 넣는 것을 적용 조건으로 둘 수 있습니다.

- Scroll Anchoring으로 뷰포트 위쪽에 콘텐츠가 삽입·제거돼도 스크롤 위치가 자동 보정돼 점프가 사라집니다.
- `:heading`이 h1~h6를 한 번에 선택하고 `<img sizes="auto">`가 레이아웃 폭을 자동 계산하며, SVG 2 정합 30건(웹페이지 67%가 SVG 사용)도 포함됩니다.

실무에서 가장 체감이 큰 건 `appearance: base-select`입니다 — 그동안 디자인 시안의 커스텀 드롭다운을 JS 컴포넌트로 새로 짜던 작업을, 네이티브 select의 접근성을 유지한 채 `::picker-icon`·`::checkmark`로 스타일링할 수 있게 됩니다. iOS Safari가 사실상 한국 모바일의 한 축이라, select·날짜 입력 같은 폼 컨트롤을 우회 컴포넌트로 두던 패턴을 표준 요소로 되돌릴 수 있는지 재점검할 시점입니다.

##### 요약

- 이름이 비슷한 네 기능을 작동 방식 기준으로 가르는 글입니다 — 헷갈려서 잘못 고르면 의도와 다른 인터랙션이 나옵니다.
- Scroll-driven은 `animation-timeline: scroll()`로 스크롤 진행도와 애니메이션을 직접 연동해, 위로 스크롤하면 애니메이션도 거꾸로 돌아갑니다.
- Scroll-triggered는 요소가 `trigger activation range` 임계를 넘으면 스크롤 속도와 무관하게 애니메이션을 끝까지 한 번 실행합니다.
- Container query scroll state는 `@container scroll-state(stuck: top)` 구문으로, 컨테이너가 특정 스크롤 조건(예: sticky로 고정됨)에 도달할 때 스타일을 바꿉니다.
- View Transitions는 "스크롤과 전혀 무관"하며, 같은 문서(same-document)·문서 간(cross-document) 상태 전환을 crossfade·커스텀 애니메이션으로 처리합니다.

##### 매거진 인사이트

> 네 기능이 비슷해 보여도, 고를 기준은 "스크롤에 비례하나, 임계에서 한 번 터지나, 컨테이너 상태에 반응하나, 스크롤과 무관한 전환인가"입니다.

실무에서 패럴랙스·진행 인디케이터는 Scroll-driven, 뷰포트 진입 시 한 번 나타나는 페이드인은 Scroll-triggered, sticky 헤더가 고정될 때 그림자를 주는 연출은 scroll-state, 목록→상세 페이지 이동의 부드러운 전환은 View Transitions로 매핑됩니다 — 잘못 고르면 "한 번만 보여줘야 할 모션이 스크롤마다 되감기는" 식의 버그가 납니다. 브라우저 지원 폭이 기능마다 다르고 iOS Safari 진입 시점도 제각각이라, 한국 트래픽의 Safari 비중을 감안해 핵심 연출은 미지원 시 정적 상태로 떨어지는 폴백을 전제해야 합니다.

각 기능을 `@supports`로 감싸고 `prefers-reduced-motion`에서 모션을 끄는 분기를 두며, scroll-state·view-transition은 still-evolving 스펙이라 운영 투입 전 회귀 테스트에 브라우저 매트릭스를 명시하는 것을 적용 조건으로 둡니다. 시안에서 "이건 진행도형인가 트리거형인가"를 디자이너와 먼저 합의하면 구현·QA 단계의 재작업을 줄일 수 있습니다.

> remote query를 "이벤트 핸들러·모듈 스코프 어디서든 `await`하는" 방향으로 정리하면서, 그 대가로 `.run()` 제거라는 breaking change를 동반합니다.

- 관련 링크 1: [원문] CSS-Tricks — Another Stab at the Perfect CSS Pie Chart… Sans JavaScript! | https://css-tricks.com/another-stab-at-the-perfect-css-pie-chart-sans-javascript/

- 관련 링크 3: [관련 표준] CSS Values 5 — sibling-index() / sibling-count() | https://drafts.csswg.org/css-values-5/#tree-counting

##### 요약

- 개별 `<li>`에 흩어져 있던 `data-percentage` 값을 부모 `<ul>`로 모아 인덱싱(`data-percentage-1`, `-2`…)으로 관리합니다.
- 업그레이드된 `attr(data-percentage-1 type(<number>))`로 HTML 속성값을 숫자형 CSS 변수로 가져옵니다.
- `--accum` 변수로 이전 슬라이스들의 누적 백분율을 `calc()`로 계산해, 각 슬라이스의 시작 각도를 잡습니다.
- `hsl(calc(360deg * sibling-index() / sibling-count()) 90% 40%)`로 슬라이스 색상을 항목 수에 맞춰 자동 생성합니다.
- 아직 미지원 환경을 위해 `:has(:nth-child(n))`로 `--sibling-count`를 수동 폴백하는 방식도 함께 제시합니다.

##### 매거진 인사이트

> 데이터는 부모가 들고, 자식은 받은 변수로 자기 몫만 그립니다.

구현 관점에서 이 글의 설계 핵심은 계산 위치입니다. 각 슬라이스가 자기 앞 슬라이스들의 합을 알아야 하는데, 자식끼리는 그 값을 공유하기 어렵습니다. 그래서 모든 백분율을 부모 `<ul>`로 끌어올려 `--accum` 누적값을 미리 계산하고, `:nth-child()`로 각 자식에게 필요한 변수만 내려주는 구조를 택했습니다. `attr()`의 `type(<number>)` 문법 덕에 속성값이 문자열이 아닌 숫자로 들어와 `calc()`에 바로 쓰입니다.

실무에서는 당장 프로덕션에 넣을 코드라기보다, `sibling-index()`·`sibling-count()`·타입드 `attr()`가 무엇을 가능하게 하는지 감을 잡는 레퍼런스에 가깝습니다. 이 함수들의 브라우저 지원이 아직 고르지 않아, 폴백 분량이 적지 않다는 점도 글이 그대로 보여줍니다. 데이터 시각화를 라이브러리 없이 CSS로 풀어볼 때, 부모 집중 계산 패턴과 폴백 비용을 함께 가늠하는 출발점으로 읽을 만합니다.

- 요약: Chrome 149가 그리드·플렉스·멀티컬럼의 gap 영역에 구분선을 표준 속성으로 그리는 CSS gap decorations를 안정 채널에 넣었습니다. 그동안 빈 div나 가상요소로 흉내 내던 칸 구분선을 `column-rule-*`·`row-rule-*` 계열 속성으로 직접 처리합니다.

##### 요약

- Chrome 149는 그리드·플렉스·멀티컬럼 레이아웃의 gap 영역에 구분선(rule)을 그리는 CSS gap decorations를 안정 채널에 추가했습니다. `column-rule-inset`·`row-rule-inset`·`column-rule-visibility-items`·`row-rule-visibility-items` 같은 속성으로 어디에·어떻게 선을 그릴지 제어합니다.
- 빈 `<div>`나 가상요소로 구분선을 흉내 내던 패턴을 표준 속성으로 대체해, 마크업을 늘리지 않고 칸 사이 선을 다룰 수 있습니다.
- `shape-outside`가 `path()`·`shape()`·`rect()`·`xywh()` 함수를 지원해 float 요소 주변 텍스트 래핑 형태를 더 자유롭게 정의합니다.
- SVG `pathLength`에 매핑되는 CSS `path-length` 속성, `image-rendering: crisp-edges`, 텍스트 상호작용 시 ellipsis를 일시적으로 clip으로 전환하는 처리도 함께 들어갔습니다.
- Stable 출시일은 2026-06-02입니다.

##### 매거진 인사이트

칸 사이 구분선을 그리려고 빈 요소를 끼워 넣어 본 경험은 그리드를 다뤄 본 퍼블리셔라면 누구나 있습니다.

gap decorations는 그 우회를 정리합니다. 선의 위치와 표시 여부를 `column-rule-inset`·`row-rule-visibility-items` 같은 속성으로 직접 잡으니, 구조용 빈 div가 사라지고 마크업이 콘텐츠 구조에만 집중합니다. `shape-outside`의 `rect()`·`xywh()` 확장도 같은 결입니다. 이미지 컷아웃 주변 텍스트 흐름을 만들 때 좌표 기반 함수로 형태를 잡을 수 있어, 잡지형 레이아웃을 이미지 마스크 없이 시도할 여지가 생깁니다.

다만 아직 Chromium 계열 단일 구현 단계라, 멀티 브라우저 폴백이 필요한 상용 페이지에서는 progressive enhancement로 얹는 게 안전합니다. 패션·뷰티 카탈로그처럼 그리드 카드 사이 구분선을 자주 쓰는 화면을 운영 중이라면 구분선용 빈 요소를 gap decorations로 걷어낼 수 있는지, 아직 도입 전이라면 `@supports`로 감싼 점진 적용 분기를 컴포넌트에 미리 설계해 둘 수 있는지 살펴볼 지점입니다.

- 관련 링크 1: [공식 사양] Visual Studio Code 1.124 Release Notes | https://code.visualstudio.com/updates/v1_124

##### 요약

- VS Code 1.124는 Autopilot을 기본 활성화하고, 작업이 실제로 끝났는지를 고정 규칙 대신 유틸리티 모델로 판단하는 Advanced Autopilot로 고도화했습니다.
- 세션 내비게이션이 키보드 중심으로 바뀌었습니다. `Ctrl+R`(macOS `Cmd+R`)로 검색 가능한 세션 피커를 열고, `Ctrl+Tab`/`Ctrl+Shift+Tab`으로 앞뒤 이동, `Ctrl+1`~`Ctrl+9`로 위치 기반 점프를 합니다.
- Background session requests — `Alt+Enter`로 세션이 로딩되는 동안 백그라운드에서 요청을 제출하고, 인터페이스는 다음 질의를 위해 비워 둡니다.
- 통합 브라우저가 방문 기록을 유지하고 URL 바에서 제안하며, Agents 창을 리로드해도 이전 세션·레이아웃·에디터 상태가 자동 복원됩니다.

##### 매거진 인사이트

> 세션 내비게이션이 키보드 우선으로 바뀌면서, 에이전트 여러 개를 동시에 굴리는 작업이 탭 전환에 가까워졌습니다.

이번 릴리스의 무게중심은 단일 에이전트가 아니라 '여러 세션을 동시에 다루는 사람'에 있습니다. `Ctrl+R` 피커와 `Ctrl+1`~`Ctrl+9` 점프, `Alt+Enter` 백그라운드 제출은 세션을 마우스로 클릭해 찾던 흐름을 키보드 컨텍스트 스위칭으로 바꿉니다. Agents 창 리로드 시 레이아웃이 복원되는 변화도 같은 맥락으로, 세션이 일회성 채팅이 아니라 유지되는 작업 공간이라는 전제가 깔립니다.

Autopilot 기본 활성화는 팀 설정에서 한 번 짚고 넘어갈 지점입니다. 완료 판단을 유틸리티 모델에 맡기는 만큼, 검토 없이 진행되는 단계가 늘 수 있습니다. 프런트엔드 팀에 에이전트 워크플로를 이미 붙였다면 세션 단축키와 백그라운드 제출을 팀 공통 단축키 가이드에 반영할지, 아직 도입 전이라면 Autopilot 기본값과 자동 진행 범위를 먼저 합의하고 켤지 정리해 둘 만합니다.
