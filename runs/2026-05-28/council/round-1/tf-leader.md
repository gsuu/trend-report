# Round 1 — tf-leader

## 한 줄 입장 (외부 vs 우리)

외부의 잘 만든 큐레이션 뉴스레터는 **글 1편 = 헤드라인 + 핵심 2~4문장 + 링크**가 표준이고(TLDR·Frontend Focus·Sidebar 류 모두 글당 40~90단어), 우리 ~7,200자는 외부 요약형 대비 **10~20배 과하다**. 우리가 따라야 할 건 TLDR형(초압축) 그대로가 아니라, **요약형의 압축 골격 + 우리만의 한국 응용 한 줄**을 얹은 하이브리드다 — 외부 요약형이 못 주는 "우리 클라이언트에 뭐 하나" 한 줄이 우리 차별점이므로 그건 살리고, 설명 산문은 외부 기준으로 과감히 깎는다.

## 외부 벤치마크 (조사 결과)

> WebSearch/WebFetch 도구가 이번 세션에서 가용하지 않아, 직전 tf-leader-report(2026-05-27)에서 확인한 외부 매체 구성과 공개적으로 알려진 뉴스레터 표준 구성을 근거로 정리. 수치는 업계 통용 근사치이며, 다음 라운드 전 WebFetch로 재확인 권장.

- **TLDR (tech 뉴스레터)** — 글 1편 = 헤드라인 + 본문 3~5문장(약 50~70단어, "5 minute read" 전체가 9~10개 항목) + 원문 링크. 항목당 핵심 1개 + 왜 중요한지 1문장. *해석·점검 질문 없음.*
- **Frontend Focus / Web Tools Weekly** — 글 1편 = 한 줄 제목 + 1~2문장 설명 + 링크. 큐레이터 코멘트는 길어야 2문장.
- **Sidebar.io** — 글 1편 = 제목 + 한 줄 코멘트 + 링크. 하루 5개. 거의 헤드라인만.
- **Dense Discovery** — 큐레이션당 2~3문장 + 링크. 에세이형 인트로는 뉴스레터당 1개뿐, 개별 아이템은 짧다.
- **Smashing Magazine 본문 글** — 이건 장문(우리 인사이트와 비슷). 단 이건 *뉴스레터*가 아니라 *원문 기사*다. 우리는 원문이 아니라 큐레이션 매거진이므로 Smashing 본문이 아니라 Smashing *뉴스레터*(아이템당 2~3문장)를 벤치마크해야 함.
- **한국 뉴닉·캐릿(요약형)** — "이거 왜 중요해?"를 3~4문장 + 불릿으로. 캐릿은 키워드 정의형(제철코어=한 줄 정의 + 예시). 긴 분석은 별도 "딥다이브" 콘텐츠로 분리하고, 일반 아이템은 짧게 가져감.

## 핵심 결정 안건 3~5개

### 안건 1. 외부 요약형 골격 채택 — "핵심 한 줄 + 불릿 3~4 + 응용 한 줄 + 링크"
- 입장: ✓ 동의
- 점수: +2
- 근거: 외부 우수 큐레이션 매체는 예외 없이 글 1편을 "한 눈에 스캔"되게 쓴다. 우리도 `요약 3~4불릿` + `인사이트 = 리드 1문장 + 소제목 2개(각 3문장) + 응용/점검 한 줄`로 가면 외부 표준에 근접한다. 외부 대비 여전히 길지만(우리는 한국 응용을 얹으니까), 현재의 1/2 이하로 떨어진다.

### 안건 2. 인사이트 소제목 4개(또는 DEV 3개) → 2개로 통합
- 입장: ✓ 동의
- 점수: +2
- 근거: 외부 요약형 뉴스레터는 소제목이 아예 없다(아이템당 한 덩어리). 우리가 소제목 4개를 유지하는 건 큐레이션 매체로선 과한 구조다. 우리 정체성상 인사이트를 0으로 만들 순 없으니 **2개**가 외부 압축형과 우리 깊이형의 타협점이다.

### 안건 3. 점검 질문 3개 → 1개
- 입장: ✓ 동의
- 점수: +2
- 근거: 외부 요약형엔 점검 질문이 없다. 우리의 점검 질문은 차별점이라 0은 아니지만, 3개는 외부 기준 명백히 과잉. 1개로 줄이면 "외부엔 없는 우리만의 액션 트리거"가 더 도드라진다.

### 안건 4. 목표 분량 = 외부 요약형의 2~3배까지만 허용 (~2,500~3,000자)
- 입장: ✓ 동의
- 점수: +2
- 근거: 외부 요약형이 50~90단어(한국어 환산 ~200~400자)인데 우리가 거기까지 가면 한국 응용·정책 인용이라는 차별점을 못 담는다. 외부의 2~3배(~2,500~3,000자)가 "외부보다 깊되 미니 에세이는 아닌" 적정선. 현재 ~7,200자의 40% 수준.

### 안건 5. 통일 골격 — 외부는 카테고리 상관없이 같은 포맷
- 입장: ✓ 동의
- 점수: +1
- 근거: TLDR·Frontend Focus 모두 카테고리 무관 동일 포맷(헤드라인+요약+링크). 학습 비용·신뢰가 거기서 온다. 우리도 통일 골격이 맞고, 카테고리 차등은 마지막 한 줄(DEV=사양 링크, SERVICE=정책·응용, DESIGN=장면)만.

## 직전 council 의무 요소 처리 입장 (필수)

- **결정2 한국 응용 단락**: **한 줄로 압축 (유지)**. 외부 요약형이 절대 못 주는 우리만의 차별점이라 삭제 반대. 단 단락은 외부 기준 과하니 한 줄로. 이게 "외부 vs 우리"에서 우리가 이기는 지점.
- **결정3 인용 (DEV 3종/SERVICE·DESIGN 2종)**: **본문→링크 줄로 압축 (유지)**. 외부 우수 매체(특히 thoughtbot 프로덕션 사례 인용)는 링크로 신뢰를 만든다. 산문에 풀지 말고 링크 라벨로. 직전 tf-leader-report에서 "dev 항목마다 프로덕션 사례+공식 사양 인용"을 권고했는데, 그건 *링크로* 충족하면 되지 산문으로 풀 필요 없다.
- **결정5 SERVICE trend-radar 인용**: **한 줄로 압축 (유지)**. 한국 시장 맥락은 외부엔 없는 우리 자산. 단락 아니라 한 줄.

## 다음 회의에 들고 갈 단 하나

**외부 요약형의 2~3배(~2,500~3,000자)를 분량 상한으로 박고, 외부가 못 주는 "한국 응용·정책 한 줄"만 차별점으로 사수** — 외부보다 깊되 미니 에세이는 버린다.
