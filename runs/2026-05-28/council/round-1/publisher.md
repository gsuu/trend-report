# Round 1 — senior-publisher

## 한 줄 입장

퍼블리셔에게 상세 페이지의 가치는 **"코드 위치 + iOS Safari/한글 조건 + 공식 사양 링크"** 세 가지지, 산문 단락이 아니다 — DEV 인사이트는 산문 3소제목을 다 풀어 쓸 게 아니라 **"무엇을 / 어디에 적용 / 어떤 조건·링크"** 골격만 남기면 본문이 절반 이하로 떨어진다. 화면 스캔성 관점에서도 ~7,200자는 스크롤 6~7번이라 그 자체로 이탈 요인이다.

## 핵심 결정 안건 3~5개

### 안건 1. DEV 인사이트 소제목 3개 → 2개 + 단락 3문장 상한
- 입장: ✓ 동의
- 점수: +2
- 근거: DEV 잠금 소제목은 `왜 지금 이 업데이트인가 / 구현 관점 / 실무에 어떻게 적용할 수 있을까` 3개. 퍼블리셔 시점에서 `왜 지금`은 요약 첫 불릿이 이미 답한다 — 인사이트에서 또 한 단락 쓰는 건 중복이다. **`구현 관점`(코드·브라우저·접근성 무엇을 봐야 하나) + `실무 적용`(우리 화면 어디에) 2개**로 통합하고, 각 단락 3문장 상한. `왜 지금`은 리드 한 문장으로 흡수.

### 안건 2. DEV 인용 3종 "세 줄 필수" → 한 줄 묶음 허용 (관련 자료 줄로)
- 입장: ✓ 동의
- 점수: +2
- 근거: 직전 council 결정3은 DEV 인용 3종(합성 데모·공식 사양·프로덕션 사례)을 **세 줄 모두 필수**로 박았다. 신뢰 근거라 삭제는 반대지만, 본문 산문 안에 세 줄을 풀면 그 자체로 한 단락이 늘어난다. **본문에서 빼서 `관련 자료` 링크 블록에 `[합성 데모]·[공식 사양]·[프로덕션 사례]` 라벨 줄로 압축.** 3종 정보 유지 + 본문 분량 0. 퍼블리셔는 링크가 본문에 풀어쓴 산문보다 더 유용하다 — 클릭해서 CodePen·MDN 바로 연다.

### 안건 3. 요약 불릿 6개 → 3~4개, DEV는 첫 2불릿에 기술명·조건 강제 유지
- 입장: ✓ 동의
- 점수: +2
- 근거: 현재 불릿이 2~3문장 완결형이라 "요약"이 아니다. **불릿당 1~2문장, 3~4개.** 단 DEV는 첫 두 불릿에 기술명·API·브라우저·접근성 조건 중 하나 이상이 들어가야 한다는 기존 룰은 유지(이게 퍼블리셔가 스캔하는 첫 정보다). 개수를 줄이되 정보 밀도 룰은 보존.

### 안건 4. 글 1편 본문 목표 ~7,200자 → ~2,800~3,200자 구조 상한
- 입장: ✓ 동의
- 점수: +2
- 근거: 화면 스캔성 기준으로 모바일 한 글이 스크롤 2~3번 안에 끝나야 한다. 제안 구조: `요약 3~4불릿` + `인사이트 = 리드 1문장 + 소제목 2개(단락 각 3문장) + 관련자료 링크줄`. 점검 질문(DEV는 없음, SERVICE/DESIGN만)도 1개. 이러면 ~3,000자 안쪽.

### 안건 5. 통일 골격 + DEV는 인용 라벨, SERVICE/DESIGN은 점검질문 차등
- 입장: ⚠️ 조건부
- 점수: +1
- 근거: 골격은 통일(요약+인사이트 2소제목)이 렌더·파서·Storybook 컴포넌트 재사용에 유리하다. JSON 섹션 스키마(`is-bullet-summary` + `is-deep-dive`)를 안 건드리고 블록 수만 줄이는 게 안전하다. 카테고리 차등은 "마지막 블록"만 다르게(DEV=관련자료 링크줄, SERVICE/DESIGN=점검질문 1개).

## 직전 council 의무 요소 처리 입장 (필수)

- **결정2 DEV 한국 4축 (iOS Safari·한글·모바일·접근성 중 1개)**: **유지, 단 한 줄로**. 이건 퍼블리셔가 가장 중요하게 보는 정보다(예: "iOS Safari 미지원 — @supports 폴백 필수"). 단락이 아니라 `구현 관점` 안의 한 문장으로 박으면 된다. 삭제 절대 반대.
- **결정3 DEV 인용 3종 세 줄**: 위 안건2 — **유지하되 본문→관련자료 링크 줄로 이동.** 세 줄 필수는 링크 라벨로 충족.
- **결정5 SERVICE trend-radar 인용**: DEV 면제 대상이라 직접 영향 없음. SERVICE 쪽 판단은 planner/trend-hunter에 맡김. 다만 본문 단락이 아니라 한 줄 인용이 맞다는 데 동의.
