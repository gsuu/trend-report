# Round 2 — tf-leader (세부 수치 단일 확정)

## 다른 4명 수치 보고 입장

Round 1에서 내가 제안한 "외부 요약형의 2~3배(2,500~3,000자)"와 다른 4명의 3,000자 권장이 거의 일치. 외부 비교 기준으로 단일값에 동의 가능.

## 확정 안건별 입장

### 1. 목표 분량 단일값 — 본문 3,000자 권장 / 3,500자 절대 상한
- 입장: ✓ +2 (내 제안 2,500~3,000에서 상한 3,500까지 수용)
- 근거: 외부 요약형(TLDR·Frontend Focus, 글당 ~200~400자)의 7~9배지만, 우리는 *큐레이션+한국 응용*을 얹는 하이브리드라 외부보다 두꺼운 게 맞다. 3,000 권장이면 외부 요약형 골격(핵심+불릿+링크)에 우리만의 인사이트 2소제목+응용 한 줄을 더한 적정선. 상한 3,500은 밀도 높은 글의 안전 마진. 외부 기준 통과.

### 2. 잠금 소제목 2개 통합 — 외부엔 소제목 없음, 2개가 우리 하한
- 입장: ✓ +1
- 근거: TLDR·Sidebar는 아이템당 소제목 0. 우리가 큐레이션 매거진 정체성상 인사이트를 살리려면 2개가 하한이고, 그 이상은 외부 기준 과잉. designer/planner의 카테고리별 2개 명칭안에 동의.

### 3. 인용 = `관련 자료` 링크줄 (외부 우수 매체의 신뢰 패턴)
- 입장: ✓ +2
- 근거: 외부 우수 매체(thoughtbot 프로덕션 사례, MDN 사양)는 *링크로* 신뢰를 만들지 산문으로 풀지 않는다. 직전 tf-leader-report에서 "dev 항목마다 프로덕션 사례+공식 사양 인용"을 권고했는데, 그건 *링크 라벨*로 충족하는 게 외부 표준에도 맞다. publisher의 라벨 3줄 방식 확정 찬성.

### 4. 점검 질문 1개 = 응용 질문 통합 (외부엔 없는 우리 차별점)
- 입장: ✓ +2
- 근거: 외부 요약형엔 점검 질문·응용이 아예 없다. 이게 "외부 vs 우리"에서 우리가 이기는 단 하나의 지점이다. 단락이 아니라 한 줄로 압축하면 외부 압축형의 효율 + 우리만의 액션 트리거가 동시에 산다. planner 통합안 강력 찬성.

### 5. 통일 골격 — 외부는 카테고리 무관 동일 포맷
- 입장: ✓ +2
- 근거: TLDR·Frontend Focus 모두 카테고리 무관 동일 골격. 우리도 통일 골격(요약+인사이트 2소제목) + 마지막 블록만 차등(DEV=링크줄, SERVICE/DESIGN=점검=응용 한 줄). 외부 표준과 정합.

## 보강 권고 (외부 비교 관점)
- 다음에 WebFetch 가용 시 TLDR·Frontend Focus 실제 글당 단어 수를 재측정해 우리 3,000자 상한이 "외부의 정확히 몇 배"인지 못 박으면 기준이 더 단단해진다. 이번엔 직전 보고서 + 통용 근사치 기준.

## 다음 회의에 들고 갈 단 하나
