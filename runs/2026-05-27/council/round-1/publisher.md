## 안건 1 — 매거진 dev 카테고리 라우팅 룰 재정의 (제외 패턴 명시 + references/dev ★ 자동 승격)

**문제** — 이번 회차 매거진 dev 7건 중 5건이 *AI 도구 비교(Copilot Alternatives) · SaaS 출시 announcement(Claude SMB, Agents for finance) · GitHub/Anthropic 관리 도구 릴리즈 노트(Issue fields, Copilot cloud agent)*다. 어느 것도 *마크업·CSS·인터랙션·접근성·UI 라이브러리·웹표준*에 닿지 않는다. 같은 날 references/dev.md는 정반대 품질(★ 5건 · sibling-index iOS Safari 26.2 stable · Gap Decorations fallback 분기 · Virtuoso Data Table 한국 원화 즉시 호환). 직전 회의록·planner·designer 모두 같은 진단(planner: "DEV 7건 비중 과다, 기획자가 가져갈 게 0건"). *문제 진단은 첫 회차에 합의된 상태.*

**제안** — `digest-collect` Phase 4(타겟 적합성 분류) 단계에 **dev 카테고리 *제외 패턴 화이트보드***를 명시 추가:
- AI 코딩 도구 비교·"Best of N" 리스티클(Copilot/Cursor/Claude Code 가격·플랜 announcement)
- SaaS 출시 announcement(Anthropic·OpenAI·Vercel 신제품 발표 자체)
- 관리 도구 릴리즈 노트(GitHub Issues fields, GitLab 권한 등)
- 코드 위치(CodePen·MDN·GitHub repo·view-source 가능 URL) 없는 글
이 4종은 *자동 dev 카테고리 제외 또는 dev 슬롯 점유 금지*. 동시에 같은 회차 `references/dev.md`의 ★ 항목은 **shortlist → 글쓰기 단계에서 매거진 dev 슬롯에 우선 자동 승격**. references-scout가 이미 본문·코드 위치·iOS Safari 적용성 다 확인한 자료라 글쓰기는 본문 확장 + 한국 회사 응용 1단락 추가만 하면 된다.

**한국 환경 적용성** — 패션 커머스 30명 퍼블리셔에게 가는 글이라는 점에서, 제외 패턴 4종 모두 *iOS Safari·한글 폰트·모바일 우선·접근성*과 무관(AI 도구 가격은 마크업과 무관). 반대로 references/dev ★ 5건은 모두 iOS Safari 지원 단계 명시·한글 폰트 처리 노트·모바일 sticky/transform 주의점 있음. 라우팅 룰 재정의 자체가 *한국 환경 적합도를 글쓰기 입력에 박는 것*과 동의어.

**점수 9/10** — 사용자 명시 합의가 첫 회차에 이미 잡혀 있고(planner도 같은 안건), 룰 변경 위치(Phase 4 + shortlist)가 명확하며, references-scout v2 산출물 품질이 검증돼 자동 승격 위험이 낮다. 1점 감점은 *제외 패턴이 너무 엄격하면 dev 슬롯이 빌 가능성* — 대안으로 SEO/GEO(이번 #06 pxd story 글) 같은 *퍼블리셔 본업 인접 영역*은 keep 룰을 같이 박아야 함.

## 안건 2 — dev 항목마다 "프로덕션 사례 1개 + 공식 사양 1개" 보조 인용 표준 (tf-leader 권고 채택)

**문제** — tf-leader 외부 벤치마크가 5건 중 sibling-index에서 *thoughtbot 프로덕션 케이스 스터디(자사 마퀴 리팩토링) + MDN 1차 사양*이 빠져 있다고 정확히 지적. 합성 데모(Smashing 본문 패턴)만 있고 *"이미 누가 production에 썼다"*는 신뢰 신호가 없으면 카카오·토스·무신사 퍼블리셔가 결정 단계에서 멈춘다. CTTD 30명 퍼블리셔도 같은 위치 — *"누가 라이브로 쓰고 있나"*가 다음 스프린트 채택 결정의 절반.

**제안** — `dev-reference-scout` 산출물의 ★ 항목 + 매거진 dev 글쓰기 단계에서 **각 항목당 최소 2개 보조 링크 강제**:
1. *프로덕션 적용 사례 1개* — thoughtbot 블로그·CSS-Tricks 알마낙·MDN Examples·한국 회사 기술블로그(토스·당근·우아한·카카오 페이) 본문에서 "실제 production에 적용했다" 명시된 글
2. *공식 사양 1개* — MDN·W3C·WHATWG·Chrome Platform Status·caniuse 1차 문서

`news-tracking/dev-sources.json`에 **thoughtbot 블로그·MDN 신기능 페이지·웹접근성연구소·NULI·토스 a11y 블로그** 추가(tf-leader 안건 1번 그대로). 매거진 글쓰기 단계의 `magazine-writer` 프롬프트에 "프로덕션 사례 + 공식 사양 보조 링크가 모두 있는가" 체크 항목 명시. 없으면 `magazine-reviewer` 단계에서 revise 루프.

**한국 환경 적용성** — 한국 회사 기술블로그(토스·당근·우아한·카카오) 본문이 *프로덕션 사례 1개*의 1순위 후보가 되어야 한다. 영어권 thoughtbot·CSS-Tricks 사례만으로 끝나면 *"한국 환경에선 어떻게 쓰는가"* 검증이 빠진다. 한국어 IME·iOS Safari·한글 폰트 처리는 한국 회사 본문에만 있는 정보다. 매거진 dev 글이 한국 회사 기술블로그 사례를 *최소 1개* 인용하는 구조가 30명 퍼블리셔 슬랙 활용도의 결정 변수.

**점수 8/10** — tf-leader 안건 1번을 그대로 받는 형태라 외부 검증 끝남. 다만 *프로덕션 사례를 항상 찾을 수 있는가*가 변수(특히 CSS 신기능은 아직 production 0인 단계 많음 — Gap Decorations·HTML-in-Canvas 등). 대안: 신기능이라 production 사례 부재 시 "production 사례 없음 — 이유: stable 출시 N주차"를 명시해 *왜 없는지*를 같이 알려준다. 1.5점 감점은 보조 인용 강제가 magazine-writer 작업 시간 증가시킨다는 점.

## 안건 3 — 한국 환경 적용성 4축 체크 필드 (iOS Safari·한글 폰트·모바일·접근성) 매거진 dev 글쓰기 *제출 요건*

**문제** — references/dev.md 자체 평가에 *"iOS Safari·한글 폰트·모바일 우선 적용성 명시 10/10 (100%)"*가 있고 이건 사실(실제 본문 확인). 그런데 매거진 dev 7건은 이 4축이 *0건도 명시되어 있지 않다*. references 작성 단계에선 4축 명시가 표준이고 매거진 작성 단계에선 안 한다는 구조적 모순. 매거진이 references보다 가벼운 글이라면 모를까, 매거진이 *최종 발행물*이고 references는 *내부 풀*이라 역전.

**제안** — `magazine-writer` 프롬프트에 매거진 dev 카테고리 글의 **본문 4축 명시 의무화**:
1. **iOS Safari 지원 단계** — stable / Tech Preview / 미지원 / 폴백 필수 중 어느 단계인가 (한국 모바일 절반이 iOS이므로)
2. **한글 폰트 처리 노트** — 한글 커스텀 폰트·서브셋·variable font 사용 시 영향(렌더링·용량·subpixel)
3. **모바일 우선 적용성** — `position: sticky` 부모 transform 금지·`will-change` 명시·`overscroll-behavior` 같은 *모바일 깜빡임* 디버깅 노트
4. **접근성** — 키보드 접근·스크린리더(한국어 NVDA·센스리더)·IME composition 영향

`magazine-reviewer` 9개 점검 항목에 *"한국 환경 4축 본문 명시 여부"* 1개 추가. 4축 중 3개 미만이면 revise 루프. 4축 모두 *"해당 없음 — 사유"*를 적는 것도 인정(예: WebGPU는 *접근성*과 *한글 폰트* 무관이지만 명시 자체는 필요).

**한국 환경 적용성** — 이 안건 자체가 *한국 환경을 글쓰기 입력에 박는 것*이라 적용성이 그 자체. 구체 케이스 — references/dev.md #4 ScrollMap의 *"sticky 부모에 transform 금지"*, #7 GSAP 3D cube의 *"will-change 명시"*가 한국 iOS 모바일 깜빡임 디버깅에 그대로 도움인 것처럼, 매거진 dev 글이 이 4축을 항상 명시하면 *30명 퍼블리셔가 본문 한 번 읽고 다음 스프린트 카르드에 그대로 옮길 수 있다*.

**점수 9/10** — 매거진 작성·검수 단계에 한 줄씩만 추가하면 되는 *낮은 구현 비용* + 매거진 dev의 질적 차별화 효과 직접적. 0.5점 감점은 디자인·서비스 카테고리에는 4축이 다 안 맞아서 *dev 카테고리 한정*인 점(다른 카테고리는 별도 룰 필요).

## 안건 4 — 패션 커머스 특유 컴포넌트 dev 사례 1-2건 명시 탐색 (룩북 hover·사이즈 차트 툴팁·컬러 스왓치·무한 스크롤·인생샷 줌)

**문제** — 직전 회의록에서 *"패션 커머스 특유 컴포넌트 직접 매칭은 sibling-index 1건만, 나머지는 시즌 룩북·증권 호가창 등 간접 응용"*이라고 본인이 평가한 부분. CTTD가 패션 이커머스 디자인 에이전시인데 references/dev.md 10건 중 *패션 컴포넌트와 직접 매칭은 1건*이라는 건 dev-reference-scout 탐색 가설 자체에 패션 컨텍스트가 약하다는 신호. trend-radar에서도 *29CM 1조 돌파·무신사 뷰티 메가스토어·올리브영 멤버스 월간 승급* 같은 한국 패션·뷰티 시장 변동이 강하게 잡힌 첫 회차에, dev 사례는 패션 컨텍스트가 빠져 있는 *비대칭*이 만들어졌다.

**제안** — `dev-reference-scout` 능동 탐색 가설에 **패션 커머스 컴포넌트 키워드 1차 시드 5종 추가**:
- *룩북 hover* — 상품 마우스 오버 시 다른 컷·다른 컬러 노출 패턴 (Awwwards·CodePen·view-source)
- *사이즈 차트 툴팁* — 사이즈 가이드 모달·반응형 비교 표 (Radix Dialog·접근성 키보드 접근 라이브 데모)
- *컬러 스왓치 키보드 접근* — `role="radiogroup"` + 화살표 키 네비·`aria-checked` 패턴
- *무한 스크롤 + 뒤로 가기 위치 복원* — `scroll-restoration: manual` + IntersectionObserver
- *상품 상세 인생샷 줌* — 핀치 줌·휠 줌·키보드 줌(`+`/`-`) 3채널 (`open-props` 활용)

직접 *무신사·29CM·W Concept·LF몰·SSF·올리브영·아모레*몰 사이트의 해당 컴포넌트를 DevTools inspect → ARIA·키보드 흐름·iOS Safari 호환 메모로 *연 1회 라운드별 1건씩이라도* references/dev.md에 박는다. trend-radar에서 *무신사 뷰티 메가스토어 Q2 오픈*이 잡혔으니 다음 회차에 *무신사 뷰티 자사몰의 800개 브랜드 카드 그리드 컴포넌트* 직접 inspect 라운드가 1순위.

**한국 환경 적용성** — 한국 패션·뷰티 자사몰 직접 inspect 자체가 *iOS Safari·한글 폰트·모바일* 실측이고, *컬러 스왓치 키보드 접근*은 한국어 스크린리더(센스리더·NVDA 한국어) 환경에서 검증해야 의미. 디자이너 180명 회의록에 *"이 컴포넌트는 무신사·올리브영이 이렇게 풀었다"* 직접 인용 가능한 풀이 됨. 패션 클라이언트 시안 회의에서 *"이거 코드로 가능?"* 물어보는 디자이너에게 *"무신사 사이즈 차트 툴팁이 이미 그렇게 풀고 있다, 이 마크업으로 가능"*을 즉답하는 기반.

**점수 7/10** — 가장 high-value 발견이 나올 수 있지만 *능동 탐색 비용*이 가장 큼(자사몰 직접 inspect는 자동화 안 됨). 능동 탐색 라운드를 *분기별 1회·매주 1건*으로 운영하는 절충안이 현실적. 3점 감점은 *자사몰 사이트가 봇 차단으로 inspect만 가능하고 본문 fetch는 막히는* 운영 리스크.

## 안건 5 — 디자인 토큰 → CSS 변수 자동화 운영기 1건 매 회차 *필수 슬롯*

**문제** — 직전 회의록 부족 영역 평가에 *"디자인 토큰 → CSS 변수 자동화 운영기(Figma Variables → Style Dictionary) 라이브 사례 0건. 핸드오프 작업 비중을 생각하면 큰 결손"*이라고 적었음. CTTD 디자이너 180명 ↔ 퍼블리셔 30명 사이의 *최대 마찰점*이 디자인 토큰 핸드오프(시안 변수가 어떻게 CSS 변수로 떨어지는가)인데, references/dev.md엔 1건도 없다. designer 회의록도 *#22 토큰이 흐르는 화면 안정시키기 — 스트리밍 UI* 1건 잡았지만 토큰 자동화는 아님. planner 회의록의 *#12 pxd 컬러 토큰 3가지 방식*은 디자이너 영역으로 분류돼 dev 풀로 안 옴.

**제안** — 매주 references/dev.md에 **디자인 토큰·핸드오프 카테고리 *최소 1건 필수 슬롯***. 후보 카테고리:
- Figma Variables → Style Dictionary → CSS 변수 배포 운영기 (한국 회사 우선: 토스 TDS·당근 carrot-ui·우아한 woowahan-design-system·카카오 KakaoUI)
