### 21. Remix 3 베타 프리뷰 — Fetch API 라우트와 새 `remix/ui`로 다시 짠 풀스택 모델

- 날짜: 2026-04-29
- 태그: Remix, Fetch API, 미들웨어, 컴포넌트 모델
- 국가: GLOBAL
- 카테고리: javascript
- 직무 태그: `웹DEV`
- 출처 유형: release_note
- 출처: Remix (Shopify)
- 출처 URL: https://remix.run/blog/remix-3-beta-preview
- 이미지: https://remix.run/blog-images/posts/remix-3-beta-preview/og.jpg
- 이미지 설명: Remix 블로그 og:image
- 요약: Remix 3 베타 프리뷰가 2026-04-29에 공개됐다. 라우트가 Fetch API 위에서 동작하고, 폼 제출과 HTML 응답이 표준 채널이 되며, 컴포넌트 모델도 새 `remix/ui`로 옮겨간다. 아직 프로덕션 단계가 아니다.

##### 용어 설명

- Remix: Shopify가 운영하는 풀스택 웹 프레임워크. 라우팅·데이터 로딩·폼 제출을 웹 표준에 맞춰 묶어 두는 것이 특징이다.
- Fetch API: 브라우저와 서버 양쪽에서 동일한 형태로 쓰는 표준 요청·응답 인터페이스. `Request`와 `Response` 객체를 그대로 다룬다.
- mixin: 컴포넌트에 스타일·이벤트·동작을 한 객체에 묶어 합성하는 패턴. 상속 대신 조합으로 기능을 더한다.

##### 요약

- Remix 3 베타 프리뷰가 2026-04-29 공개됐다. `npx remix@next new my-remix-app`으로 설치할 수 있고, 원문은 "not production ready yet"이라고 못 박는다.
- 라우트는 Fetch API 라우트로 바뀌었다. 컨트롤러가 `Response`를 직접 반환하고, 미들웨어가 요청 수명 주기를 소유한다. RPC 레이어를 두지 않고 폼 제출(URL 기반)과 HTML 응답을 표준 채널로 사용한다.
- 컴포넌트는 `remix/ui`에서 가져온다. `Frame`은 독립적으로 로드·내비게이션·리로드되는 서버 렌더 UI 단위다. `Handle<T>`는 상태와 props를 다루는 제네릭 타입, `on()`은 이벤트 핸들러 선언 함수, `mix`는 스타일·이벤트·동작을 배열로 합성하는 시스템이다.
- 풀스택 지향을 명시한다. 라우트·컨트롤러·미들웨어·세션·인증·폼·업로드·에셋·데이터·DB 관리까지 한 프레임워크 안에 둔다. 의존성 최소화와 "unbundling" 전략으로 런타임 중심 모델을 채택한다.
- 권장 사용처는 실험·데모·프로토타입·피드백 수집으로 한정한다. 마이그레이션 가이드와 안정화 일정은 아직 공개되지 않았다.

##### 매거진 인사이트

###### 왜 지금 이 업데이트인가

Remix 3는 RPC 레이어를 빼고 폼 제출과 HTML 응답을 표준 채널로 끌어올린다. 라우트는 Fetch API의 `Request`/`Response`로, UI는 `remix/ui`의 `Frame`과 `mix` 합성으로 옮겨가며, React 의존도를 라우팅·데이터 채널 바깥으로 밀어낸다. Shopify가 자사 이커머스 스택을 끌고 있는 프레임워크가 이 방향을 잡았다는 점이 가장 큰 신호다.

###### 구현 관점

라우트가 Fetch API 위에 올라가면 미들웨어 체인, 인증 토큰 검증, 응답 캐싱 정책을 표준 객체로 다룬다. 폼이 URL로 제출되고 서버가 HTML을 돌려주는 구조에서는 클라이언트 번들이 줄고, 부분 업데이트는 `Frame`의 독립 내비게이션으로 처리한다. `Handle<T>`로 타입 안전 props를 유지하고 `on()`으로 이벤트를 바인딩하는 모델은 React의 hook 사용 규칙과는 결이 다르다. 기존 React 컴포넌트·상태 관리·테스트 도구를 그대로 옮기기 어렵다.

###### 실무에 어떻게 적용할 수 있을까

지금 단계에서 운영 코드 이전을 검토할 시점은 아니다. "not production ready yet"이라는 원문 표시를 그대로 받아들여야 한다. 다만 Shopify 기반 헤드리스 PDP, 체크아웃, 검색 결과처럼 폼 제출과 부분 갱신 비중이 큰 화면은 Remix 3 모델로 옮길 분기점이 될 수 있다. 사내에서는 베타 빌드로 작은 라우트 하나를 시범 작성해 `Frame` 단위 분리, 미들웨어 책임 경계, `remix/ui`와 사내 디자인 시스템의 충돌 지점을 먼저 점검하는 정도가 적절하다. 정식 안정 버전과 마이그레이션 가이드가 나오기 전까지는 평가용 트랙으로만 운용한다.
