### 25. CSS에 들어온 네이티브 랜덤 — `random()`과 `random-item()`이 바꾸는 변주 설계

- 날짜: 2026-05-06
- 태그: CSS, random, 마이크로 인터랙션, 디자인 토큰
- 국가: GLOBAL
- 카테고리: HTML/CSS
- 직무 태그: 웹디자인 웹DEV
- 출처 유형: blog_opinion
- 출처: CSS-Tricks
- 출처 URL: https://css-tricks.com/the-importance-of-native-randomness-in-css/
- 이미지: CSS-Tricks 본문 hero (발행 시 직접 캡처)
- 이미지 설명: CSS-Tricks 'The Importance of Native Randomness in CSS' 본문 상단 hero 이미지
- 요약: CSS Values and Units Module Level 5에 `random()`과 `random-item()`이 정식 도입되면서, 그동안 JS와 전처리기로 우회하던 변주를 CSS 안에서 선언적으로 다룰 수 있게 됐다.

##### 용어 설명

- CSS Values and Units Module Level 5: CSS 값과 단위에 관한 W3C 명세의 최신 레벨로, `random()`·`random-item()` 같은 새 함수형 값을 정의한다.
- `random-item()`: 인자로 넘긴 값 리스트 중 하나를 임의로 골라 돌려주는 CSS 함수. 색상·각도·문자열 등 단일 값이 들어갈 자리에 모두 쓸 수 있다.

##### 요약

- CSS Values and Units Module Level 5에 두 함수가 추가됐다. `random()`은 지정한 최솟값·최댓값 사이의 임의 값을 돌려주고, `random-item()`은 주어진 리스트에서 하나를 골라 돌려준다.
- 그동안의 우회법은 네 갈래였다. `:nth-child()`와 애니메이션을 조합한 의사 랜덤(기계가 패턴을 금방 읽어낸다), `Sass`·`SCSS`·`Less` 같은 전처리기의 컴파일 시점 random(빌드한 순간 값이 얼어붙는다), 서버 사이드 렌더(요청마다 새 값이지만 동적으로 추가되는 DOM은 못 따라간다), 그리고 JS(런타임 진짜 랜덤이지만 표현 책임이 스타일 레이어를 벗어난다).
- 글쓴이는 활용 사례로 임의 배경색, confetti나 falling snow 같은 마이크로 인터랙션, 제너레이티브 레이아웃과 디자인 시스템의 미세 변주를 든다. 변주가 있어야 자연스럽게 보이는 화면을 CSS 안에서 처리할 수 있다는 의미다.
- 핵심 주장은 'Rule of Least Power'다. 선언적 문제는 선언적 도구로 풀어야 하고, 레이아웃 결정은 다시 CSS로 돌아와야 한다. 글쓴이는 이를 두고 CSS가 '스타일 언어에서 제너레이티브 레이아웃 시스템으로' 옮겨가는 변화라고 정리한다.

##### 매거진 인사이트

###### 왜 지금 이 업데이트인가

지금까지 화면에 변주를 주려면 거의 항상 JS가 필요했다. 찜 버튼 누른 순간 색종이가 흩날리는 효과, 로딩 인디케이터의 흔들림, 빈 상태 일러스트의 색 조합 — 사용자에게 '살아 있는 화면'으로 느껴지게 하는 디테일은 대부분 스타일 레이어 밖에서 결정됐다. CSS에 `random()`이 들어온다는 건 이 결정 권한을 다시 스타일 레이어로 끌어오는 일이다. 디자인 토큰으로 색·각도·지속시간을 정의해 둔 시스템이라면, 그 토큰의 변주 범위까지 CSS 안에서 한 줄로 선언할 수 있다.

###### 구현 관점

`random-item()`은 디자인 토큰 리스트와 가장 잘 붙는다. 브랜드 컬러 팔레트를 토큰으로 갖고 있다면 confetti 조각의 `background-color`나 빈 상태 카드의 강조색을 `random-item(var(--brand-1), var(--brand-2), var(--brand-3))` 식으로 묶어둘 수 있다. `random()`은 각도·지속시간·offset처럼 연속적인 값에 쓴다. falling snow의 낙하 시작 위치, 마이크로 인터랙션의 회전 각도, 스켈레톤 로더의 미묘한 폭 차이 같은 자리다. 글쓴이가 이전 워크어라운드를 짚으며 강조한 점은 분명하다. `:nth-child()` 패턴은 기계가 곧바로 읽어내고, 전처리기 random은 빌드 시점에 값이 굳고, JS 랜덤은 표현 결정을 스타일 밖으로 빼낸다. 네이티브 함수는 이 세 한계를 동시에 풀어준다. 다만 이 글에 브라우저 지원 현황은 언급되지 않았으니, 도입 전에는 별도로 호환성 테이블과 폴백 전략을 확인해야 한다.

###### 실무에 어떻게 적용할 수 있을까

가장 먼저 손볼 자리는 마이크로 인터랙션이다. 찜 버튼 클릭 피드백, 주문 완료 confetti, 결제 성공 화면의 작은 모션, 빈 상태 일러스트의 강조색 같은 곳은 변주가 있어야 같은 모먼트를 여러 번 봐도 식상하지 않다. 지금까지 JS로 처리해 온 이 영역을 CSS 토큰 변주로 옮기면, 디자이너는 팔레트와 범위만 토큰 문서에 추가하면 되고, 개발자는 한두 줄짜리 declaration으로 끝낼 수 있다. 두 번째 자리는 제너레이티브 배경이다. 카테고리 카드 배경, 빈 추천 슬롯, 프로모션 캐러셀의 placeholder처럼 '있어도 그만 없어도 그만'인 자리에 토큰 기반 미세 변주를 넣어 화면 밀도를 낮추지 않으면서 같은 컴포넌트가 반복되는 인상을 줄일 수 있다. 도입 순서를 잡을 때는 한 가지를 분리해 두는 게 안전하다 — '모든 사용자에게 동일하게 보여야 하는 화면'(예: 결제 금액·재고 상태)에는 쓰지 않고, '같아도 다르게 보이는 편이 자연스러운 화면'(피드백·placeholder·장식)에만 토큰 변주를 적용하는 식이다.
