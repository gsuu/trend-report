### React Doctor — React 코드베이스 진단 도구, AI 에이전트에 규칙 설치 지원

##### 용어 설명

- React Doctor: React 코드베이스를 정적 분석해 품질 점수와 개선 진단을 출력하는 오픈소스 CLI 도구. `npx -y react-doctor@latest .` 한 줄로 실행한다.

##### 요약

- `npx -y react-doctor@latest .` 명령으로 현재 디렉터리의 React 코드베이스를 스캔하며, 보안·성능·정확성·아키텍처 4개 영역을 검사한 뒤 0~100 사이의 점수와 실행 가능한 진단 목록을 출력한다.
- `--diff [base]` 옵션으로 기본 브랜치 대비 변경된 파일만 스캔할 수 있어, PR 단위 리뷰나 CI 파이프라인에서 변경분만 검사하는 방식으로 쓸 수 있다.
- `--staged` 옵션은 스테이징된 파일만 검사해 사전 커밋 훅(pre-commit hook)으로 걸기 적합하고, `--fail-on <level>` 옵션으로 `error`, `warning`, `none` 중 하나를 지정해 CI 종료 코드를 제어할 수 있다.
- `--annotations` 옵션을 켜면 GitHub Actions 주석 형식으로 결과를 출력하고, `--json`으로 구조화된 JSON 보고서를 뽑을 수 있어 별도 리포팅 도구와 연결하기 쉽다.
- Claude Code, OpenAI Codex, Cursor, GitHub Copilot, Windsurf, Cline 등 50개 이상의 코딩 에이전트를 지원하며, `npx -y react-doctor@latest install` 한 번으로 현재 환경에 활성화된 에이전트에 React 품질 규칙을 심는다.
- `-y` 플래그는 비대화형 환경(CI, 코딩 에이전트)에서 프롬프트를 건너뛰기 위해 필수로 붙이도록 명시하고 있다.

##### 매거진 인사이트

###### 왜 지금 이 도구인가

AI 코딩 에이전트가 React 코드를 생성하는 비중이 늘면서, 생성 결과물이 React 관례와 얼마나 맞는지 자동으로 확인해야 한다는 필요가 커졌다. React Doctor는 이 진단 단계를 CI 파이프라인 또는 커밋 이전 훅으로 당겨 넣을 수 있도록 설계되어 있고, 에이전트에 직접 규칙을 설치하는 기능까지 붙어 있다. 생성 단계에서 규칙을 심으면 이후 수동 리뷰 단계에서 걸러야 하는 항목을 줄일 수 있다.

###### 구현 관점

커밋 전 단계에 넣으려면 `--staged`와 `--fail-on error`를 조합해 사전 커밋 훅을 구성한다. CI 파이프라인에서는 `--diff main`으로 PR에 포함된 변경분만 스캔하고, `--annotations`로 GitHub Actions 주석을 활성화하면 PR 리뷰 화면에서 바로 위치별 진단 결과를 확인할 수 있다. `--json` 출력을 이용하면 점수 추이를 별도 대시보드에 축적해 코드베이스 품질 변화를 추적하는 운영 방식도 가능하다. 다만 도구가 잡아내는 구체적인 규칙 목록과 각 규칙이 점수에 기여하는 방식은 원문에서 공개되지 않아, 실제 어떤 패턴이 감지되는지는 스캔 결과를 직접 확인해야 한다.

###### 실무에 어떻게 적용할 수 있을까

바이브 코딩 방식으로 Claude Code나 Cursor가 생성한 React 컴포넌트를 그대로 커밋하기 전에, React Doctor 사전 커밋 훅이 먼저 걸리도록 설정하면 생성 코드의 품질 기준을 팀 공통으로 유지할 수 있다. 에이전트에 규칙을 설치하는 `npx -y react-doctor@latest install` 기능은 생성 단계부터 규칙을 인식하게 만드는 방향인데, 설치 이후 에이전트가 실제로 어떤 규칙을 따르는지 팀 내에서 먼저 검증해볼 필요가 있다. 기존 React 코드베이스가 있다면 `--score`로 현재 점수를 먼저 측정하고, 스프린트 단위로 점수 변화를 추적하는 기준으로 사용할 수 있는지 점검해보는 것이 시작점이 될 수 있다.
