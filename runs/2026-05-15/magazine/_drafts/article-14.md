### 로컬 AI를 기본값으로 — 클라우드 의존을 끊을 수 있는 유스케이스와 판단 기준

##### 용어 설명

- Brutalist Report: 저자 Cyrus가 직접 만든 뉴스 애그리게이터 서비스. iOS 클라이언트에서 로컬 AI 모델로 기사 요약을 처리한다.
- LanguageModelSession: Apple이 제공하는 온디바이스 AI 모델 접근 API. 서버 연결 없이 기기 내 신경처리장치(Neural Engine)를 사용한다.

##### 요약

- 저자는 OpenAI·Anthropic API에 과도하게 의존하는 방식이 "의도하지 않은 분산 시스템을 기능으로 포장하는 것"이라고 비판한다. 서버 다운, 신용카드 만료, 레이트 제한처럼 외부 공급업체에 묶이는 취약성, 데이터를 제3자로 전송하는 순간 발생하는 프라이버시 문제가 근거다.
- Brutalist Report iOS 앱에서 기사 요약 기능을 `LanguageModelSession`(Apple 로컬 모델 API)으로 구현했다. 기사 데이터가 이미 기기에 있으므로 서버 전송이 불필요하고, 사용자 로그 기록·공급업체 계정·"30일간 콘텐츠 저장" 같은 약관도 필요 없다.
- 긴 콘텐츠는 약 10,000자 단위로 청크 분할 후 요약을 통합하는 방식으로 처리했다.
- Apple의 `@Generable` Swift 구조체 패턴을 쓰면 마크다운 파싱이나 JSON 스키마 없이도 타입이 보장된 구조화 출력을 만들 수 있다고 소개한다.
- 저자가 제시하는 판단 기준은 단순하다. "모델 역할이 사용자 소유 데이터를 변환하는 것"이면 로컬로, "세계 지식이 필요한 검색 엔진"이면 클라우드로. 요약·분류·추출·재작성·정규화처럼 입력이 이미 기기에 있는 단일 변환 작업은 "천재 모델이 필요 없다"는 것이다.

##### 매거진 인사이트

> 신뢰는 2,000단어 개인정보 보호 정책으로 만들어지지 않는다 — 처음부터 그런 정책이 필요 없게 설계할 때 만들어진다.

###### 왜 지금 이 논의인가

클라우드 LLM을 기본값으로 두는 패턴이 빠르게 굳어지는 상황에서 나온 반론이다. 저자는 "게으름"이라는 표현을 쓰지만, 실질적 문제는 더 구체적이다. 외부 API에 연결된 순간 네트워크 의존성·공급업체 가용성·레이트 제한·데이터 유출 가능성이 한꺼번에 붙는다. Apple이 `LanguageModelSession` 같은 온디바이스 추론 API를 정식 제공하고, 로컬 모델 생태계가 실제 배포 가능한 수준으로 성숙한 지금이, 이 선택지를 진지하게 검토할 시점이라는 게 글의 전제다.

###### 구현 관점

이 글은 Apple 생태계의 온디바이스 API(`SystemLanguageModel.default`, `LanguageModelSession`)를 중심으로 쓰였다. 웹 환경에서는 직접 적용할 수 없지만, 판단 구조는 가져올 수 있다. 민감 데이터를 다루는 파이프라인 — 예: 사용자 입력 텍스트를 분류하거나 요약하는 서버사이드 처리 — 에서 Ollama 같은 로컬 추론 서버를 두고 클라우드 API 호출을 대체하는 유스케이스가 같은 맥락이다. 주의할 점은 저자가 명시하지 않은 부분이다. 하드웨어 비용과 모델 성능의 상한이 여전히 장벽이고, "기기에 이미 데이터가 있다"는 전제 자체가 서버 처리 파이프라인에서는 성립하지 않는다. 로컬이 항상 답이 아니라, 작업 유형과 데이터 위치가 일치할 때만 유효한 선택지다.

###### 실무에 어떻게 적용할 수 있을까

내부 개발 도구나 민감 데이터를 다루는 파이프라인에서 클라우드 LLM 호출을 로컬 모델로 전환할 때 이 글의 판단 기준이 ROI 계산의 출발점이 된다. 먼저 작업을 분리해야 한다. 요약·분류·추출·재작성처럼 입력이 완결된 변환 작업은 로컬 전환 후보다. 세계 지식을 검색하거나 다단계 추론이 필요한 작업은 클라우드가 맞다. 다음은 데이터 위치다. 처리 대상 데이터가 이미 사내 시스템에 있다면, 굳이 외부 API로 보낼 이유를 먼저 검증해야 한다. 마지막은 장벽 체크다. 로컬 추론은 GPU·RAM 비용과 모델 성능 상한이 현실이다. "로컬로 충분한가"가 아니라 "클라우드를 써야만 하는 이유가 있는가"를 먼저 확인하는 방향으로 질문을 바꿔보는 것이 이 글의 실질적 제안이다.
